Test engineer with a physicist's training.

I design and automate tests for systems that combine hardware, firmware and software, and write the verification documentation that goes with them. Before engineering I spent six years in astrophysics, ending with doctoral research in Leiden. Based in Motala, Sweden.

How I work

  • Requirements before tests

    A test is only as good as the requirement it traces to, so I start by making requirements testable.

  • Automate what repeats

    Steps that run more than twice become a sequence, with results anyone can reproduce.

  • Data before conclusions

    Research taught me to check assumptions against measurements before trusting a result.

  • Documentation that gets used

    Verification documents and reports written for the next engineer, not only for the archive.
