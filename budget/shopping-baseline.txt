Shopping item interaction / layout V4
=====================================
Status: FINISHED / HOME-PARITY MODEL
- The previous V2 approach still depended on Shopping's old startEditItem -> renderItems -> delayed focus path and was not sufficiently responsive on iPhone.
- V4 changes the visible item interaction to the same model as Home: the visible text becomes contenteditable immediately in the original user click, without re-rendering before the keyboard/focus step.
- The entire text area / remaining row hit area enters edit mode; the user does not need to tap exactly on a letter.
- Enter commits the edit; Escape cancels; leaving the row commits.
- Only after editing completes is the value persisted through Shopping's existing startEditItem/saveEditItem data path, so sh_lists and existing Firebase sync remain authoritative.
- Normal item rows copy Home's geometry: 20px checkbox / flexible text / 22px delete action, Home-style spacing, borders, checkbox, editable-field treatment and ~.16s transitions.
- A small × delete action is added at the right, matching the Home shopping row layout.
- Category names are edited inline without an initial re-render.
- Pressing Enter while editing a category heading saves the heading and immediately opens a new article input beneath that heading, restoring the fast heading -> article flow.
- Add-item and add-category rows are focused immediately from the same click gesture.
- Desktop and mobile included.

Shopping yellow/category routing V5
===================================
Status: FINISHED
- V4 layout and interaction logic remain unchanged.
- Category headings are slightly larger while retaining the compact Home-derived layout.
- Shopping item accents are changed from blue to Shopping yellow: checkbox tick/border/glow and inline edit border/glow.
- Items can now be typed/edited with a category/store suffix exactly like Home, e.g. "Mjölk (Willys)" or "Kaffe (Maxi)".
- The suffix is case-insensitively matched against existing category headings.
- On save, the visible item text is cleaned to "Mjölk" / "Kaffe" and the item is physically moved under the matching heading.
- If the heading does not exist, behavior follows Home: the cleaned item is moved to the uncategorized top area.
- New-item save, checkbox-draft save and inline item edits all use the same routing behavior.
- Recipe ingredients support the same suffix syntax. Recipe text may retain the suffix so the recipe remembers its intended store, while the shopping-list item is cleaned and routed under the matching category.
- Recipe add-to-shopping and recipe ingredient checkbox actions use category-aware insertion.
- Recipe checked-state UI is refreshed against the cleaned shopping item text so category routing does not break checkbox mirroring.
- A narrow child-list-only observer on #recipes-list refreshes recipe checkbox state after recipe re-renders; it does not observe text/attributes and does not mutate DOM structure.
- Desktop and mobile included.

Recipe persistence / compact recipe UI V3
=========================================
Status: FINISHED
- Root cause of disappearing recipes was the legacy recipeSessionStore implementation: recipes were stored only in RAM and sh_recipes was explicitly deleted on each DOMContentLoaded.
- V3 replaces the recipe UI/function path with a persistent recipe store under sh_recipes_v3.
- Recipe data includes an updatedAt timestamp and is synchronized directly to Firebase Realtime Database at sh_recipes_v3 for cross-device persistence.
- Local and remote recipe stores reconcile by timestamp; newer remote data updates the page without requiring a reload.
- Recipe creation, rename, ingredient add/edit/delete, recipe dropdown and "add recipe to shopping list" now use the persistent V3 store.
- Ingredient edits continue to add/sync the ingredient into the currently selected shopping list, using the existing sh_lists data so normal list Firebase sync remains unchanged.
- Recipe ingredient checkboxes mirror the matching item in the active shopping list.
- "+ Lägg till ingrediens" remains permanently available at the bottom of every open recipe.
- Recipe name and ingredient edit fields focus immediately after render for faster iOS typing.
- Recipe presentation is compact: smaller vertical spacing, tighter nested ingredient list, compact + / × actions, smaller section spacing and responsive mobile sizing.
