Shopping list engine V7
=======================
Status: ACTIVE / ROBUST SINGLE-STATE MODEL

Root-cause analysis of previous add/edit bugs
---------------------------------------------
- Legacy saveNewItem stored TWO records on the first Enter: the real item plus an empty placeholder item.
- The next Enter was therefore handled by a different function, handleItemKeydown, instead of the same add path.
- V4/V5/V6 then layered capture-click, category routing and blur wrappers over those two different legacy paths.
- Re-rendering an input could trigger blur/cancel/save against an element that had just been removed, producing disappearing items and inconsistent next-row creation.
- Mobile add/edit inputs used 13–14 px text; iOS Safari auto-zooms focused form fields below 16 px, which caused the visible zoom when moving to the next item.

V7 design
---------
- Legacy Shopping V4/V5/V6 list modules are no longer loaded by auth-gate.
- A single module, budget/shopping-list-engine-v7.js, owns normal shopping item/category rendering and add/edit state.
- No empty placeholder item is ever stored in sh_lists. A new item exists only as a DOM/state draft until it contains text and is committed.
- Category -> Enter saves the category and opens one draft item editor under that category.
- Draft item -> Enter saves exactly one item and immediately opens exactly one new draft after it.
- The same draft path is used for item 1, item 2, item 3, etc.; there is no switch to a second legacy keydown path.
- Existing item -> Enter saves the edit and opens a new draft immediately after that item.
- Blur/click outside saves non-empty item/category drafts but does not create an extra next row.
- Escape cancels the active edit/draft.
- Draft/editor text is mirrored into JS state on every input event, so an incidental render cannot discard partly typed text.
- The list uses contenteditable for item/category/draft editing, avoiding iOS input auto-zoom in the main Shopping flow.
- Recipe/native text inputs are forced to at least 16 px on mobile to avoid Safari focus zoom there as well.
- While an editor/draft is active, sh_lists firebase-sync events are handled in place and prevented from triggering the legacy full-page reload that could otherwise destroy the active draft.
- Whole-row click target, Home-derived spacing/geometry, yellow checkbox/edit accents and larger category headings are retained.
- Desktop and mobile included.

Category/store suffix routing
-----------------------------
- Native in V7 for normal Shopping items: "Mjölk (Willys)" saves as "Mjölk" under Willys.
- Matching is case-insensitive.
- Unknown headings follow Home behavior and place the cleaned item in the uncategorized area.
- Routing works for new items and existing item edits without wrapping the Enter/blur state machine.
