Shopping list engine V7
=======================
Status: ACTIVE / SINGLE-STATE MODEL

- budget/shopping-list-engine-v7.js owns normal shopping item/category rendering and add/edit state.
- No empty placeholder items are stored in sh_lists.
- Category -> Enter saves the category and opens one item draft.
- Item draft -> Enter saves exactly one item and opens exactly one new draft.
- The same path is used for item 1, item 2, item 3, etc.
- Existing item -> Enter saves the edit and opens a new draft after that item.
- Blur saves non-empty drafts but does not create an extra row.
- Escape cancels the active editor.
- Draft text is mirrored to JS state on every input event.
- Main item/category editing uses contenteditable to avoid iOS form-input zoom.
- (Willys)/(Maxi) suffix routing is native in V7 for normal shopping items.
- Unknown category suffixes follow Home behavior and move the cleaned item to uncategorized area.
- Yellow Shopping accents and Home-derived row geometry are retained.

Shopping rapid-interaction stability V8
=======================================
Status: ACTIVE

- budget/shopping-list-stability-v8.js is loaded BEFORE the V7 engine so its capture-phase guards are registered first.
- Late focusout events immediately following Enter are suppressed for a short transition window.
- Repeated/held Enter events are ignored during the transition window.
- Delete actions have a short 115 ms acceptance guard to prevent accidental cascading deletion as rows shift.
- Local sh_lists firebase-sync echoes are ignored briefly after accepted local mutations to avoid redundant DOM churn.
- Separator lines between normal items/add-item rows are removed.
- Item rows are more compact while retaining the existing item text size.
- "+ Lägg till artikel" matches "+ Lägg till rubrik" size.
- Checkbox squares are slightly larger than before.

Recipe persistence / linked headings V4 + link popup V5
========================================================
Status: ACTIVE

- budget/shopping-recipes-v4.js remains the authoritative recipe persistence/render layer.
- Storage and Firebase continue using sh_recipes_v3 and preserve optional recipe URLs.
- Each recipe stores: id, name, optional url, items.
- The recipe heading opens its URL when a URL exists; chevron remains expand/collapse only.
- Recipe ingredients still use V7 category-aware insertion, including (Willys)/(Maxi) suffix routing.
- Recipe checkbox state is read against the V7 shopping engine.
- budget/shopping-recipe-link-popup-v5.js adds the current link-management UI without replacing recipe persistence.
- The old pencil is replaced visually/functionally by a real chain-link SVG icon.
- Link icon and recipe delete × are grouped at the far right of the recipe heading and have larger mobile touch targets.
- Clicking the chain-link icon opens a compact modal popup for entering/editing/removing the recipe URL.
- URL entry validates http/https and automatically prefixes https:// when needed.
- Saving/removing a link updates the same local sh_recipes_v3 store and Firebase value, then re-renders recipes.
- Existing inline recipe editing is name-only; the URL field for existing recipes is hidden there so link management has one dedicated path.
- New recipe creation may still accept an optional URL at creation time.
- Recipe delete stays an unboxed × symbol.
- Mobile popup input is 16 px to avoid Safari focus zoom.
